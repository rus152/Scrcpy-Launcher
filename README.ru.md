# Scrcpy Launcher

[English version](README.md)

Лаунчер для Windows на Flet (Material Design 3) для bundled `scrcpy 5.0` и
`adb 37`. Он показывает устройства ADB, подключает их по USB или Wi‑Fi (в том
числе через сопряжение беспроводной отладки Android 11+) и открывает выбранные
Android-приложения, каждое в своём окне виртуального дисплея scrcpy.

- Интерфейс на русском и английском, язык можно сменить в любой момент.
- Профили запуска и избранное для каждого приложения, хранятся локально для
  каждого устройства.
- Окна приложений продолжают работать при выключенном экране телефона, в том
  числе на Android 17.
- Уровень заряда устройства в верхней панели.

## Запуск

Требуются Windows, Python 3.13+ и телефон с включённой отладкой ADB.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

При первом запуске программа спрашивает язык интерфейса и проверяет
`scrcpy/scrcpy.exe` и `scrcpy/adb.exe`. Если комплект отсутствует, она
предлагает скачать
[официальный Windows-архив scrcpy 5.0](https://github.com/Genymobile/scrcpy/releases/tag/v5.0)
и распаковывает его в каталог `scrcpy/` рядом с `main.py`. Загрузку можно
отменить. Системная установка ADB не используется.

## Подключение телефона

Программа открывается списком устройств. Нажмите на телефон, чтобы подключиться
и загрузить его приложения.

### USB

1. На телефоне включите «Для разработчиков» и «Отладка по USB».
2. Подключите кабель и подтвердите RSA-ключ на экране Android.
3. Нажмите **Обновить** и выберите устройство со статусом **Онлайн**.

**Не авторизован** означает, что нужно разблокировать телефон и подтвердить
ключ. **Офлайн** означает, что ADB пока не готов: переподключите устройство или
обновите список.

### Wi‑Fi Pair (Android 11+)

1. Подключите ПК и телефон к одной Wi‑Fi сети.
2. На телефоне откройте «Для разработчиков» → «Беспроводная отладка» →
   «Подключить устройство с кодом».
3. В программе нажмите **Подключить по IP / Pair**, затем **Сопряжение**, и
   введите IP, **порт Pair** и код с телефона.
4. После сопряжения программа ищет отдельный порт подключения через mDNS. Если
   сеть блокирует mDNS, введите IP и **порт подключения** из настроек
   беспроводной отладки в **Диспетчере устройств**.

Порт Pair и порт подключения различаются; порт Pair для подключения не подходит.

### Неподдерживаемые устройства

Часы и ТВ-приставки Android определяются автоматически и помечаются
**Не поддерживается**: часы не умеют запускать приложение на отдельном дисплее,
а ТВ-приставка открывает приложение на экране телевизора, оставляя окно scrcpy
пустым.

## Приложения и профили

Каталог строится по полному выводу
`pm list packages --user <текущий пользователь>`, поэтому в нём есть и
приложения без обычной launcher-активности. Включите **Системные пакеты**,
чтобы увидеть предустановленные.

Названия и иконки загружает `launcher/resources/icon-dumper.dex`: программа
временно отправляет его через ADB в `/data/local/tmp/scrcpy-launcher` и
запускает через Android `app_process`. Помощник не устанавливается как APK, не
появляется в списке приложений и не требует root. Android сам отрисовывает
обычные, векторные и adaptive icons в единый формат PNG 144×144 с одинаковой
безопасной зоной. Три ADB-процесса обрабатывают независимые пачки приложений
параллельно. Результат хранится в постоянном локальном кэше с учётом
устройства, пакета и его `versionCode` вместе с названием и системным статусом,
поэтому при следующем запуске обрабатываются только новые или обновлённые
приложения. Если прошивка запрещает `app_process`, иконки извлекаются из APK
через ADB. Scrcpy не участвует в построении интерфейса и применяется только при
запуске выбранного приложения.

**Профиль запуска** создаёт профиль для конкретного устройства и пакета. У
каждого параметра профиля есть переключатель **Глобальные**: он берёт значение
из глобальных параметров scrcpy; выключенный переключатель задаёт
индивидуальное значение, в том числе явное выключение булевого параметра.
Экспертные аргументы передаются без shell; `--serial`, `--new-display` и
`--start-app` зарезервированы за лаунчером.

Кнопка со звёздочкой добавляет приложение в избранное. В режиме плиток
избранные показываются отдельной группой **★ Избранные** над группой **Все**;
поиск и фильтр системных пакетов действуют на обе. В таблице избранные пакеты
отмечаются `★` и поднимаются вверх. Профили и избранное ведутся отдельно для
каждого физического устройства; вместе с настройками они хранятся в локальной
SQLite-базе в `%LOCALAPPDATA%`, а не в проекте и не на телефоне.

Каждый запуск выполняет эквивалент команды:

```text
scrcpy --serial <устройство> --new-display[=<размер>/<dpi>] --start-app=[+]<пакет>
```

Поэтому каждое приложение Android открывается в отдельном окне виртуального
дисплея, и таких окон может быть несколько одновременно. Нажатие на запущенное
приложение переключает на его окно; **Активные сеансы** показывают открытые
окна и их логи.

## Выключенный экран и Android 17

На Android 17 (флаг `separate_timeouts`) любой обычный виртуальный дисплей
попадает в группу питания основного экрана, и окно приложения гаснет вместе с
экраном телефона. Поэтому лаунчер использует патченный сервер scrcpy
(`launcher/resources/scrcpy-server-5.0`), который создаёт дисплей через
`VirtualDeviceManager`: он продолжает работать при выключенном экране и после
кнопки питания. Для этого нужна CDM-ассоциация для `com.android.shell`, которую
лаунчер создаёт сам на устройствах, где она нужна. Подробности, пересборка и
удаление ассоциации — в [android-helper/README.ru.md](android-helper/README.ru.md).

## Настройки лаунчера

Кнопка настроек рядом с заголовком открывает язык интерфейса, режим при запуске
(плитки или таблица), базовый цвет темы M3, оформление (светлое, тёмное или
системное) и переключатель, подхватывающий акцентный цвет Material You с
подключённого телефона.
